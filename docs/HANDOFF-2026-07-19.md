## 2026-08-03 — INBOUND BODY BLINDNESS FIXED (PR open: `inbound-body-fix`)

**Root cause (docs-verified):** Resend's `email.received` webhook event is
ENVELOPE-ONLY — `data.email_id`/from/to/subject/message_id, NO text/html/
headers. The inbound webhook read `d.text || ''` off the payload, so every
real email reply wrote an empty-Body Conversations row (54 of 55 email-inbound
rows blind; Raw Headers literally `'{}'`; `Message Id` never written), the
classifier read an empty string, and the whole reply machine ran blind.

**Fix (Part 1, webhook):** when payload text+html are blank and an email id is
present, fetch content from `GET api.resend.com/emails/receiving/{email_id}`
(5s timeout, fail-soft: envelope row + visible `[content fetch failed — see
inbox]` marker + loud Telegram warning). Classifier runs after content
resolution. `Message Id` now persisted (restores the mid dedup paths — payload
headers were empty, so they never fired). Identity fallback: token → referral
From-match → Consumers → Ranchers (case-insensitive exact-address); pure guard
never overwrites token context. Classifier extracted verbatim to
`lib/inboundClassify.ts`.

**Fix (Part 2, backfill):** `POST /api/admin/backfill-inbound-bodies` — admin
auth + `INBOUND_BACKFILL_ENABLED=1` double latch, cap 50/run, 500ms pace,
matches blind rows to Resend's received-emails listing by bare-From +
timestamp (no Resend id was stored), writes Body/Body Plain/Raw Headers/
Message Id, re-runs CLASSIFIER ONLY (pinned: no sends, no per-row Telegram;
one summary signal). Unretained rows get `[content unrecoverable]`.
`{"dryRun":true}` = zero-write preview. Idempotent on non-empty Body Plain.

**LANDMINE:** the `.env.local` `RESEND_API_KEY` is INVALID (probed 08-03,
"API key is invalid" — same class as the dead Resend MCP key). Prod's runtime
key is what the code uses; if the backfill 502s with "listing failed", check
the key before anything else. Backfill aborts without stamping when the
listing is unreachable.
